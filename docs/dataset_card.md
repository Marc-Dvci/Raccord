# Dataset card — AccessPulse demonstration and benchmark data

AccessPulse ships with no downloaded dataset. Everything it measures is generated by the
digital twin from **original content written for this project**. This card documents what that
content is, how the benchmark corpus is drawn from it, and what the data does and does not
support.

| Dataset | What it is | Size | Licence |
|---|---|---|---|
| *The Lumière Protocol* | Original programme: dialogue, scene descriptions, translations | 12 lines × 4 languages, 5 described scenes, 85 s loop | Apache-2.0 (this repository) |
| Fault library | Declarative fault specifications = benchmark ground truth | 45 faults | Apache-2.0 |
| Benchmark corpus | Seeded stratified draw over the fault library | 1,000 scenarios | Generated; seed 20260803 |
| Calibration corpus | Injected known parameters vs probe estimates | 328 measurements | Generated |
| Slice matrix | The audience dimensions everything is measured across | 4 lang × 5 territories × 3 player builds | — |

---

## 1. *The Lumière Protocol* — the programme

**Provenance: entirely original.** Every line of dialogue, every scene description and every
translation was written for this project. No third-party film, script, subtitle file, recording
or dataset is used anywhere in this repository. See [MEDIA_RIGHTS.md](MEDIA_RIGHTS.md) for the
rights manifest and `test_demonstration_media_is_original` for the assertion that keeps it true.

**Composition** (`src/accesspulse/media.py`):

- 12 timed dialogue lines, 3 speakers (ELIAS, NOOR, ARCHIVIST), 3 scenes, 85-second loop
- 4 languages: English, French, German, Spanish — each line fully translated
- 5 scene descriptions with importance weights, authored **into the dialogue gaps**, which is
  what makes the description-masking probe meaningful
- Declared sign-language feed: fr-LSF
- Described languages: en, fr

**Why a timed event list rather than an encoded video.** The probes consume exactly the
structures a real decoder would hand them — timed dialogue tokens, timed caption cues,
described-audio windows, interpreter-feed frame statistics — so the measurement code is the
same. The benefit is that the entire demonstration runs on a laptop with nothing to download and
nothing to license. The cost is stated in the limitations below.

**Language and content.** The dialogue is deliberately mundane and non-sensitive: three
archivists arguing about a missing reel. It contains no personal data, no real names, no real
organisations, and nothing that could be distressing.

**Translation quality.** The four language versions are human-written parallel text, not machine
translation. They are close paraphrases of each other by design, because caption drift must be
measurable against the dialogue in the *promised* language.

## 2. The fault library — ground truth

45 declarative fault specifications (`src/accesspulse/faults.py`). Each carries the failing
component, the audience slices it reaches, how the symptom develops, which SLOs it should
breach, the change event that truly caused it (where there is one), which catalogued actions
genuinely fix it, and a difficulty weight.

**Distribution by feature:**

| Feature | Faults |
|---|---|
| Captions | 19 |
| Sign language | 8 |
| Accessible player | 8 |
| Audio description | 7 |
| Alternate audio | 1 |
| Accessible authentication | 1 |
| Accessible purchase | 1 |

**By onset:** 32 step, 8 ramp, 5 intermittent. **By difficulty:** 0.2 to 0.85.

**The separation that makes the benchmark meaningful.** `faults.py` is read by the simulator and
by the benchmark scorer, and by *nothing else*. The probes, the scope agent, the diagnosis
ranker and the verification suites never import it. The agents are scored against a
specification they cannot see.

**Where the faults come from.** They are modelled on failure modes that are well documented in
live media operations — timing-reference failover, encoder pool degradation, manifest omission,
track selection failure on connected-TV builds, keyboard traps in player menus, interpreter feed
freeze. They are our reconstructions, not incident reports from any organisation.

## 3. The benchmark corpus

`build_corpus(scenarios, seed)` — a **stratified** draw:

1. every one of the 45 faults appears at least once, so nothing is silently untested;
2. the remainder is sampled with weight `0.5 + difficulty`, so harder faults appear more often;
3. every scenario carries its own deterministic seed, so any single scenario can be replayed
   exactly: `accesspulse hero --fault <id>`.

The published run is 1,000 scenarios at seed 20260803 across 4 languages × 5 territories × 3
player builds, including **US as a control territory that no fault in the library touches** —
which is how scope precision is measurable at all.

Artefacts: [`bench/results/scenarios.jsonl`](../bench/results/scenarios.jsonl) (one row per
scenario, 1,000 rows) and [`bench/results/summary.json`](../bench/results/summary.json).

**Class balance is deliberately uneven.** Captions carry 448 of the 1,000 scenarios because
captions carry 19 of the 45 faults and the hardest ones. Per-feature results are reported
separately in [BENCHMARK.md](BENCHMARK.md) precisely so that the headline number cannot hide a
feature the system is bad at.

## 4. The calibration corpus

328 measurements (`bench/calibration.py`): 160 drift, 100 omission, 48 language-identification,
20 abstention. Each injects a known parameter and compares it to what the probe reported. See
[model_card.md](model_card.md) §3.1 for results.

---

## 5. Session aggregates

The only structure in the system derived from "viewers" is `SessionAggregate`, and in the
demonstration those viewers are synthetic: counts computed from territory base populations and
platform shares. They carry no identifiers by construction, are k-anonymised at k = 50, and
suppressed slices report zero with `suppressed=True`. In a real deployment the shape is
unchanged — which is the point of [PRIVACY.md](PRIVACY.md).

## 6. Limitations and biases

1. **A twin is not the world.** Fault symptoms are generated from parameterised models, not
   captured from production. The benchmark measures whether the system reasons correctly about
   *these* symptoms; it does not establish accuracy against real broadcast incidents.
2. **The programme is 85 seconds long and loops.** Long-form phenomena — hour-long slow drift,
   ad-break boundaries, mid-programme language switching — are not represented.
3. **Four languages, all European, all Latin script.** Nothing here tests right-to-left text,
   CJK line breaking, or languages whose caption conventions differ substantially. The metrics
   would need revisiting before claiming coverage of them.
4. **One sign language (fr-LSF), technical metrics only.** No signed-content dataset exists here
   and none is implied.
5. **The fault library is ours.** Its distribution reflects our judgement of what matters, not a
   measured frequency distribution from industry incident data. A fault class we did not think
   of is not in the benchmark.
6. **Difficulty weights are authored, not derived.** They stratify the draw and define the
   "hard subset"; they are a designer's estimate.
7. **Synthetic audience sizes.** Impact figures ("sessions protected") are arithmetic over
   modelled populations. They are internally consistent and useful for comparison between
   scenarios; they are not a claim about any real audience.
8. **In-sample language profiles.** The identifier is fitted on this corpus and evaluated on it
   ([model_card.md](model_card.md) §3.1).

## 7. Reproduction

```bash
accesspulse bench --scenarios 1000          # the full run, seed 20260803
python -m bench.harness --scenarios 200 --workers 7
python -m bench.harness --ablations-only --workers 7
python -m bench.calibration --out bench/results/calibration.json
accesspulse hero --fault cap.progressive_drift
```

Everything is deterministic given the seed. No network access, no credentials, no downloads.
